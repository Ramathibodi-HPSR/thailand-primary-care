# PC_MAP — Spatial Coverage of Thailand's Primary Care System

An interactive map estimating how much of Thailand's population lives within
a given walking/travel radius of a primary care facility (public facilities,
pharmacies, nurse/midwife clinics, and private clinics).

**Live dashboard:** published via GitHub Pages from [`dashboard/`](dashboard/).

## Repository layout

```
PC_MAP/
├── data/
│   ├── raw/            # source inputs — not reproducible by the scripts below
│   └── processed/       # intermediate/analysis outputs of the pipeline
├── scripts/             # the data pipeline (raw -> dashboard bundle)
└── dashboard/            # the static site GitHub Pages deploys
    └── data/             # the published data bundle (generated by scripts/)
```

### `data/raw/` — source inputs

| File | What it is |
|---|---|
| `hospitals_confirmed.csv` | Reviewed registry of primary-care facilities (id, name, type, coordinates). |
| `coverage.parquet` | Population within each 0.1–10km radius step of every facility. Computed externally in ArcGIS Pro (buffer analysis over a WorldPop-derived population raster) — **not reproducible from this repo alone**. |
| `coverage_public.parquet` | Same idea, restricted to *public* facilities only. This is its own separate GIS run (population allocated to the nearest *public* facility within radius), not a filtered subset of `coverage.parquet` — filtering by facility ID would silently undercount, since a person's nearest facility overall may be private even when a public one is also in range. |
| `province_population.json` | Total population per province, used to express coverage as a percentage. |

If you need to regenerate these raw files, see the upstream GIS project
(ArcGIS Pro buffer analysis over facility points + population raster).
Everything downstream of them is scripted and reproducible.

### `scripts/` — the pipeline

Run in order (or all at once):

```bash
pip install -r requirements.txt
python scripts/build_all.py
```

| Script | Reads | Writes |
|---|---|---|
| `01_build_coverage_totals.py` | `coverage.parquet` | `dashboard/data/coverage_distance.json` |
| `02_build_public_coverage_totals.py` | `coverage_public.parquet` | `dashboard/data/coverage_distance_public.json` |
| `03_build_province_coverage.py` | `coverage.parquet`, `province_population.json` | `data/processed/coverage_province.json` |
| `04_build_facility_lookup.py` | `coverage.parquet` | `dashboard/data/coverage_lookup.json` |
| `05_prepare_dashboard_bundle.py` | `hospitals_confirmed.csv` | `dashboard/data/hospitals_confirmed.csv` |

`scripts/common.py` defines the **published radius steps** — a tiered
resolution rather than every 0.1km out to 10km, to keep the browser-facing
bundle small:

- every 0.1 km from 0.1 to 1.0 km (short walking distances, most granular)
- every 0.5 km from 1.0 to 5.0 km
- every 1.0 km from 5.0 to 10.0 km

This cuts `coverage_lookup.json` from ~127MB to ~24MB with no loss of
precision where it matters most. To change the tiers, edit
`_build_keep_radii()` in `scripts/common.py` and re-run the pipeline — the
dashboard reads the available radii directly from the published JSON, so the
slider adapts automatically.

### `dashboard/` — the published site

Plain HTML/CSS/JS (Leaflet for the map, Chart.js for the coverage chart, no
build step). `dashboard/data/` holds the generated JSON/CSV bundle so the
folder is self-contained and deployable on its own.

To preview locally:

```bash
cd dashboard
python -m http.server
# open http://localhost:8000
```

GitHub Actions (`.github/workflows/static.yml`) deploys `dashboard/` to
GitHub Pages on every push to `main`.

## Updating the data

1. Re-export `coverage.parquet`, `coverage_public.parquet`,
   `hospitals_confirmed.csv` and/or `province_population.json` into
   `data/raw/` from the upstream GIS analysis.
2. Run `python scripts/build_all.py`.
3. Commit and push — the dashboard redeploys automatically.
